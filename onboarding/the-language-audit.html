The language audit

Angel walked the cashier screens in Italian, then the Felix screens in German, Italian, French and English, and sent 41 screenshots. This is what they found, what the code says, and — the only part that matters — what to fix first.

The one-line version

It is not one bug. It is five, they have different causes, and only one of them was ever visible to an automated check. A string with no key is English in every language — so German and French are hit exactly as hard as Italian, not less.

Read the counts as instruments, not facts. A, D and B are exact. C and E are floors — deliberately conservative patterns, so the true number is higher. And A's first two versions said 409 before the harness was corrected twice. Nothing here is a hand audit.

The five classes what actually goes wrong

A  No key at all — 359 strings

Plain English text in the template with nothing marking it translatable. Shelf Intake is the proof: in French, Italian and German it is byte-identical English — only the bottom nav bar changes. Same for the Audit Cockpit and What the till couldn't find.

B  The key exists and its value is English — FIXED, 50572bf

This page first said 27 agerep.* keys. The truth was 45 of 45, in both French and Italian — the entire namespace, copied from English and never translated. My count only included multi-word strings, so Alcohol, Today, Period, When and Reason were invisible to the instrument written to find them. German had been done properly, so it served as the sense-check for all 90 new strings.

Two stragglers elsewhere, same class: status.ok was System OK in German while French and Italian both translate it; reports.vat_total was VAT total in French while German says MWST Total. Both taken from their own siblings. Now 0 in all four, bar class_standard = Standard, the same word in every language.

This was the class Angel's eyes found and no instrument did — it passes key-parity at 100%, because a string missing from all four languages equally is not a gap any comparison between them can see.

C  Written in JavaScript, never reaches t() — 10+

Transaction History's date range — Today · Last 7 days · Last 2 weeks · This month — is a list of JS literals at transactions.html:378. Also roleDisplay(), which is why the header reads felix | Owner and pam | Cashier in every language.

D  A key that resolves in no language — FIXED, 50572bf

All 14 fell back to the English in the tag, in all four languages. Two were photographed: reorder.by gave Riassortimento · by layla and Réapprovisionnement · by layla; the four settings.join_* keys put an English New-member join offer block under an Italian heading.

One of them would have shipped a new visible bug. settings.join_offer_hint contains <b> tags and data-i18n sets textContent — so simply supplying the key would have printed A <b>one-time</b> discount on the screen. It needed data-i18n-html, which exists for exactly this. Every one of the 14 was checked for markup before a single value was written.

E  English inside an x-text expression — 61+

The hole the harness was actively hiding: it treated any element with x-text as covered, which is right about the element and wrong about the expression. x-text="'yours: ' + form.barcode" is English in German, Italian and French, on the product modal. So is '% ready' on every cleanup row. And so is the cashier's own button — scan.html:284 spells out '⚠️ Confirm' and '➕ Add to cart' inside the expression.

WITHDRAWN — the two "wrong language" boxes I was wrong

This section said, earlier today, that checkout.html was hard-coded German and receipt.html hard-coded Italian, and that a French cashier would get German at the terminal and Italian on the paper. Both claims are wrong. Neither string can reach the shop.
  • checkout.html — a SANDBOX SIMULATOR. TWINT auflegen and simulate decline live in a mock Worldline terminal that only renders when payment_provider === 'worldline_sim'. Artemis is Phase 1, which is manual, so terminal.show never becomes true. Not shop text at all — and Phase 1 integrates no Worldline, which was settled on 2026-09-05.
  • receipt.html:91 — Italian ON PURPOSE. It is the Italian legal disclaimer, printed only when isNonFiscal() — an Italian-regime tenant with no wired RT certificate — so a clean-looking receipt is never mistaken for a documento commerciale. Translating it would break the thing it exists to do.
Both had a comment saying so, three lines above the string — "Only shown for a card/TWINT sale on a worldline_sim store" and "Italian by design — it is the legal disclaimer for IT". That is LESSON #10 word for word: before filling an empty field, grep for its name in the comments, because a design that rejected something usually left a note saying so. I read the string and not the paragraph above it, and put both into a page written for Angel to steer by. Corrected the same session, before any code was changed on the strength of it.

What this costs the count: 2 of checkout.html's 11 bare strings are sandbox-only, so the real checkout screen has 9. Nothing else moves.

Three things NOT to "fix" read before touching

  • The gun's German menu words. Shelf Intake says Daten hochladen, Anzahl der gescannten Barcodes, Normalmodus. Those are printed on the scanner's own firmware menu. They must stay German in every language, because that is what the person is reading off the device in their hand.
  • Category names. Filters & Tips, Accessories (general) are the shop's own catalogue data, not UI. Translating them would change the data.
  • The de-CH numeric dates. 6.9.2026 on a document is the shop's country, by design — settled 2026-09-05. Only day and month names follow the reader.

What this page cannot tell you the honest limit

Nothing here says whether a translation that exists is any GOOD. That is the class Angel opened the morning with — "bad italian translations" — and no harness in this repo can see it. Sistemazione for the cleanup report is a real word, real Italian, and wrong. The Italian workbench button reads Banco, inside the app called Banco. The cleanup screen is Coda di sistemazione in Italian and Cockpit du catalogue in French — two different metaphors for one screen.

And the standing gap has not moved: nobody who speaks French or Italian has read any of these strings. Angel has no French. Fixing all 359 gets the English off the glass; it does not make the Italian good. Those are two different jobs and only one of them can be done from here.

One layout note while we are here: in French the product modal's save button reads Enregistrer les modifications and wraps onto three lines, making it roughly twice as tall as the German and Italian ones. Cosmetic, French only, real.
