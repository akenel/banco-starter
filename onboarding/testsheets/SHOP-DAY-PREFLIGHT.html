What this is: the things to check before you're standing in the shop, and the things to prove while you're there. One line each, with what "good" looks like.

Notes go in Banco, not here. Use the in-app feedback button — it captures the screenshot and creates the BL. This sheet is only for tracking what you tried, so nothing gets forgotten in the rush.
Triage as you go — mark the BL with one of these:
LevelMeansExample
SHOWSTOPPER A customer cannot be served, money cannot be taken, or data is lost. Checkout won't complete · scanner doesn't find a real product · totals wrong
HYPERCARE It works, but it's painful enough that staff will avoid it. Add-product needs a user switch · label takes 30s · three taps too many
NOTE Cosmetic or "would be nice". Real, but not this week. Wrong icon · German label reads oddly · column too narrow
Only SHOWSTOPPER gets fixed tonight. Everything else goes on the deck.
Part A — the night before (at home, on the ProBook)

A1 · Machine sanity 10 min

This laptop is a browser + printer + scanner. It does not run the Banco stack — 8 GB won't take Docker with Keycloak, and you'd spend the day debugging that instead of the shop.

  1. Confirm it points at the server, not localhost. the kiosk URL is https://banco.wolfhold.app/... — no Docker running on this laptop.
  2. Check free memory with the browser open: free -h at least ~2 GB available. If not, close things — XFCE + Firefox should leave plenty on 8 GB.
  3. Confirm it survives a reboot onto the kiosk user without you typing anything. power on → auto-login as kiosk → kiosk route loads. No password prompt.
  4. Check the shop's wifi is saved and reconnects after the reboot. it comes back on its own — you won't want to be typing a wifi key at the counter.

A2 · Label printer 15 min

Full detail in onboarding/08-label-printer.md. This is the short path.

  1. Install CUPS + the USB bridge, and kill the phantom-queue daemon: sudo apt install -y cups cups-ipp-utils ipp-usb sudo usermod -aG lpadmin $USER sudo systemctl disable --now cups-browsed then log out and back in so the group takes.
  2. Plug the printer in, switch it on, wait for the LCD to light. lsusb | grep -i brother shows it — but note it shows even when OFF. Trust the LCD.
  3. Create the queue: lpadmin -p BancoLabel -E -v "ipp://localhost:60000/ipp/print" -m everywhere -D "Banco label printer" lpadmin -p BancoLabel -o CutMedia=EndOfPage lpadmin -d BancoLabel lpstat -v shows only BancoLabel.
  4. Install the keepalive — without it the browser's Print silently does nothing after ~10 min idle: sudo ./scripts/install-label-keepalive.sh "Installed and running", and the timer shows in the list.
  5. Print one from the browser. Hard-refresh first (Ctrl+Shift+R). a label on the roll, ~4s. The preview should look like a label, not a small thing on a big white sheet.
  6. The real test: leave it 30 minutes untouched, then print again without touching anything. a label comes out on its own. This is the one that used to fail.

A3 · Both scanner guns 10 min

A gun is just a keyboard that types fast and presses Enter. Test both — they may differ.

  1. Open a text editor, scan a product with gun 1, then gun 2. the digits appear and the cursor jumps to a new line (that's the Enter). Both guns behave the same.
  2. In Banco, use the 📊 Barcode tab — not 🔍 Search — and scan. the product is found and added.
    Known trap: a barcode typed into the Search tab shows all products instead of one. Use the Barcode tab.
  3. Scan a label we printed (not the manufacturer's). reads back the same code, e.g. 2000000217963 → the right product.
  4. Check the built-in camera as fallback (the 📷 button). camera opens and reads a code. Useful when a gun walks off.

A4 · The add-a-product path 10 min decide tonight

The kiosk boots as kiosk, which can't add to the catalogue. Someone will need to tomorrow. Rehearse it now — don't discover it at the counter.

  1. From the kiosk, switch user → log in as Felix → add a product → switch back. it works, and you know how many seconds it takes. If it's horrible, that's a HYPERCARE BL, not a tomorrow fix.
  2. Time it. Write the number down. under ~30s is liveable. Over a minute and staff will simply stop adding products.
Do not add a staff login to the kiosk tonight. New code the evening before a shop test is how you arrive with a broken kiosk. A PIN unlock inside the kiosk is the right long-term answer — next week.

A5 · Mobile 5 min

  1. Open Banco on the phone, log in, scan with the phone camera, view a product. works on the shop wifi. Note anything that's unusable at phone width.
Part B — at the shop (Thursday)

B1 · Cold start the real test

Everything off overnight, exactly as staff will find it. First impression is the whole product.

  1. Power on the laptop and the printer. Touch nothing else. boots to the kiosk, catalogue loads, printer LED green.
  2. First action of the day: scan a product and print its label. both work first time, no warm-up, no restart. If this fails it's a SHOWSTOPPER — a shop can't start the day with a fix-it ritual.

B2 · Scan the shelf — 50 to 200 products

Volume finds what one scan never will: the odd barcode, the missing product, the slow page.

  1. Work through real stock. Every miss gets a BL with a photo of the item. most scan straight through. Count the misses — that number is the catalogue's real quality score.
  2. Watch for slow-down as the day's transactions build up. the catalogue stays quick. If it drags after 100 scans, BL it with the time of day.
  3. Deliberately scan something not in the catalogue. it fails helpfully — offers to add it, rather than a dead end or a raw error.

B3 · A real day, faked

Mimic what they actually sold. Not a demo path — the messy one.

  1. Ring up 10–20 baskets with the fake cash box. Mix cash, change, several items, an 18+ item. totals and VAT are right, age prompt fires, change is correct.
  2. Do the awkward ones: remove a line mid-sale, a discount, a refund, a held order. each recovers cleanly. These are where tills usually break.
  3. Have Felix or Pam do five sales while you stand back and say nothing. they get through without asking. Every question they ask is a BL — that's the most valuable data of the day.
  4. Print shelf labels for 10 products, stick them on, scan them back off the shelf. every one scans. This closes the loop: catalogue → label → shelf → till.

B4 · End of day

  1. Run the closeout / cash count against the fake box. the number matches what's in the box. If it doesn't, that's a SHOWSTOPPER.
  2. Power everything off, wait a minute, power back on. comes straight back to a working kiosk. No manual steps.
  3. Before you leave: read your BLs back and mark each SHOWSTOPPER / HYPERCARE / NOTE. you leave with a sorted list, not a feeling. Triage in the shop while it's fresh — not on the train.
If something breaks and you're stuck: the label printer's usual fault is a stale ipp-usb — sudo systemctl restart ipp-usb fixes it in ~5s and queued jobs then flush. Everything else: write the BL, work around it, keep going. A day of real use is worth more than a day of debugging — you can fix things at home, but you can't re-run Thursday.
